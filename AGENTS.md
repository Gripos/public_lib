## Синхронизация моделек (коллекция)

Когда пользователь просит «синхронизировать модельку/модельки/коллекцию»:

1. Запусти из корня репозитория:
   ```powershell
   npm run sync
   ```
   Это штатный и единственный способ. Скрипт — `scripts/sync-collection.mjs`.
2. Источник по умолчанию: `D:\Github\MainObsidian\6. Коллекции`.
   Переопределить: `npm run sync -- "D:\путь\к\vault"` или `$env:COLLECTION_SRC = "D:\путь"`.
3. Куда пишет: заметки → `public_lib/Коллекции/`, обложки → `public_lib/static/covers/`.
4. Проверь результат: нужная заметка появилась/обновилась, у неё `cover: covers/<файл>`,
   а сам файл обложки есть в `public_lib/static/covers/`.
5. Если в выводе есть `Cover download FAILED` — просто запусти `npm run sync` ещё раз.

Что делает скрипт:
- копирует `*.md`, кроме бренда `Welly` (они пропускаются намеренно);
- вырезает блоки ` ```dataviewjs ` и добавляет `quartz-properties: false`;
- нормализует `sku` до цифр для `Kaido House` и `Mini GT`;
- скачивает внешние обложки и переписывает `cover:` на локальный путь.

Важно:
- Скрипт **ничего не удаляет**. Устаревшие заметки/обложки удаляй вручную.
- Фильтра по одной модели нет — синкается вся папка-источник. Это безопасно:
  лишние файлы не удаляются, но в выводе могут появиться другие новые модели.
- Сборка сайта после синка не запускается. Для просмотра: `npm run sync:serve`
  или `npx quartz build` / `npx quartz build --serve`.
- Не коммить изменения, пока пользователь явно не попросит.

## Копирование отзыва (игра, фильм, книга, сериал и т.п.)

Автоскрипта для отзывов нет — копируй вручную. Пример-эталон: `Half-Life 2`.

1. Источник: `D:\Github\MainObsidian\5. Отзывы\<категория>\<Название>.md`.
   Категории: `Игры`, `Фильмы`, `Книги`, `Комиксы`, `Песни`, `Сериалы`
   (у сериалов внутри ещё `Сериалы/` и `Аниме/`). `Цитаты` — короткие цитаты,
   обычно без `type`, на витрину они не попадают.
2. Приёмник: `public_lib/Обзоры/<Название>.md` — **плоско**, без подпапок
   (категория задаётся полем `type` во frontmatter, а не папкой).
3. При копировании приведи заметку к виду сайта:
   - добавь в frontmatter `quartz-properties: false`;
   - удали блок ` ```dataviewjs … ``` ` (карточка в Obsidian на сайте не нужна);
   - удали H1 `# <Название>`, если он есть: Quartz сам рисует заголовок.
     У игр H1 обычно есть, у фильмов/книг сразу идёт `### 📖 Отзыв`;
   - обложку из `cover:` скачай в `public_lib/static/covers/<slug>.<ext>` и
     замени `cover:` на `covers/<slug>.<ext>`. `<slug>` — латиница в kebab-case:
     `Half-Life 2` → `half-life-2`, `Дюна` → `duna`; при совпадении добавь суффикс.
     Скачивать: `curl.exe -L "<url>" -o "public_lib\static\covers\<slug>.jpg"`
     (расширение — по реальному типу: `.jpg`, `.png`, `.webp`);
   - остальной frontmatter не трогай: `type`, `rating`, `genre`/`author`,
     `publisher`, `status`, `date`, `tags` нужны витрине. `type` должен быть
     непустым (`Игры`, `Фильмы`, `Книги`, `Комиксы`, `Песни`, `Сериалы`, `Цикл`).
4. Витрину `public_lib/Обзоры/Витрина обзоров.md` руками не правь: запрос
   `base` сам берёт все заметки из `Обзоры/` с непустым `type` и группирует
   по `type`.
5. Проверь: заметка лежит в `Обзоры/`, `cover` локальный, файл обложки есть в
   `static/covers/`, `type` заполнен. Если в тексте есть локальные картинки
   (`![[...]]`), скопируй их в `public_lib/static/` и поправь ссылки.
6. Просмотр: `npx quartz build --serve`. `npm run sync:serve` тоже подойдёт,
   но он дополнительно синкает коллекцию моделей.

Эталон `Half-Life 2`:
- было: `5. Отзывы\Игры\Half-Life 2.md` с внешним Steam-URL в `cover`,
  блоком `dataviewjs` и заголовком `# Half-Life 2`;
- стало: `public_lib/Обзоры/Half-Life 2.md` с `cover: covers/half-life-2.jpg`,
  без `dataviewjs` и без H1; обложка — `public_lib/static/covers/half-life-2.jpg`.
